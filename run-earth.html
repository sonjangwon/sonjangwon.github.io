Problem · Concept

콘셉트가 먼저, 기능은 그 위에

타깃은 러닝을 습관으로 만들고 싶은 20~40대입니다.

기존 러닝 앱은 훈련과 기록에 집중합니다. 누적 레벨 같은 장치가 있어도 숫자나 색깔로 보여주는 기록 기능의 부가 요소에 가깝습니다.

Run Earth는 반대로 "내가 달린 거리만큼 지구를 여행한다"는 하나의 콘셉트를 먼저 정하고 기능을 그 위에 올렸습니다. 한 번 달릴 때의 기록이 아니라 지금까지 쌓인 거리가 지구 위 어디쯤에 와 있는지를 보여주고, 서울에서 출발해 국내 도시와 해외 G20 수도 18곳을 거쳐 부에노스아이레스에 도착하면 한 바퀴가 끝납니다.

기록이 흘러가는 길

러닝은 산속이나 지하처럼 통신이 끊기는 곳에서도 합니다. 그래서 기록은 기기에 먼저 저장하고(local-first), 서버는 연결될 때 뒤따라 올라가는 두 번째 사본으로 둡니다. 달리는 순간부터 계정을 지울 때까지, 기록 한 건이 기기와 서버 사이를 어떻게 오가는지입니다.

Decisions

의사결정과 트레이드오프

"기록은 절대 잃지 않는다"를 실제 동작으로 옮기면서 마주친 분기점들입니다.

D-01
기기 DB 먼저 vs 서버 저장 먼저

통신이 끊긴 곳에서 뛴 기록을 지키기 위해 기기 DB를 1차 저장소로 두고 서버는 뒤따라 올리도록 했습니다. 동기화 정책에서는 두 가지를 정했습니다. 업로드가 실패해도 재시도를 포기하지 않고, 한 건이 실패해도 다음 건은 막지 않는다.

재시도를 포기하면 오래 오프라인이던 기록이 영영 올라가지 못하고, 깨진 한 건이 뒤의 모든 기록을 붙잡게 되기 때문입니다. 올릴 대상이 러닝 기록 하나뿐이라 별도의 동기화 큐는 만들지 않았습니다 — 같은 데이터를 두 곳에 두는 비용만 생기기 때문입니다.

D-02
백그라운드 추적 먼저 vs 강제 종료 대비 복원 먼저

야외 테스트는 성공했지만, 화면을 켜고 뛰었기 때문이었습니다. 폰을 주머니에 넣으면 거리가 쌓이지 않았습니다. 원래는 앱이 강제 종료됐을 때를 대비한 복원(스냅샷)을 먼저 만들 계획이었지만, 순서를 뒤집어 화면이 꺼져도 추적을 이어가는 포그라운드 서비스를 먼저 붙였습니다.

복원은 손실을 줄이고, 포그라운드 서비스는 손실을 막습니다. 앱이 죽어 있는 동안에는 GPS도 꺼져 있어서, 복원해도 경로에 구멍이 남습니다. 복원은 그 뒤에 안전망으로 추가했고, 실측값을 바탕으로 두 가지 저장 방식을 계산해 비교한 끝에 더 단순한 쪽을 택했습니다. 유실을 막으려는 기능이 복잡해서 버그가 나면 본말전도이기 때문입니다.

D-03
0km 기록은 저장하고 세는 것만 바꾸기 vs 저장 막기

거리 0km 기록에는 성격이 다른 두 가지가 섞여 있었습니다. 잘못 눌렀다 바로 끈 것과 뛰었는데 GPS를 못 잡은 것. 데이터만으로는 구분되지 않습니다. 다른 러닝 앱처럼 저장을 막으면 GPS 실패 기록까지 사라지고, "뛰었는데 앱이 안 세줬다"는 최악의 경험이 됩니다.

그래서 전부 저장하고, 거리가 사실상 0이면서 1분도 안 된 기록만 '미완료'로 보아 통계와 스트릭에서 뺐습니다. 시간 조건이 두 유형을 가릅니다. 이 과정에서 코드를 열어보니 스트릭에 거리 조건이 아예 없었습니다. "매일 뛰었다"가 "매일 START를 눌렀다"가 되어 앱의 핵심 동기 장치가 무력화되어 있던 것을 함께 고쳤습니다.

Verification

실측으로 잡은 문제들

정적 분석과 테스트를 통과한 뒤에도, 야외에서 직접 달리며 측정해야 드러난 문제와 해결 방법입니다.

V-01
화면을 끄자 거리가 35% 부풀었다
Cause

화면을 끄면 안드로이드가 위치 갱신을 3초에서 8~11초로 늦췄고, 그 사이 GPS 흔들림이 몰려 들어와 시속 65km 같은 불가능한 구간이 25개 생겼습니다.

Fix

초속 6m를 넘는 좌표는 버리고, 30초 넘게 끊긴 뒤 돌아온 구간은 거리에서 뺐습니다.

Result

5.14km로 잘못 기록됐던 러닝이 3.52km로 바로잡혔습니다.

V-02
거리는 맞는데 경로가 틀렸다
Cause

같은 기기 · 같은 빌드에서 절전 모드만 바꿔 대조 측정해 원인을 절전 모드로 확정했습니다.

절전 ON절전 OFF
정확도 중앙값20m4m
30m 넘게 튄 점프19건0건
최대 샘플 간격205초7초
Fix

필터를 더하지 않고 START 전에 경고하는 방식을 택했습니다. 정상 데이터에는 걸러낼 좌표가 없어서 필터를 넣어도 효과를 검증할 수 없었기 때문입니다.

V-03
에러 없이 실패하는 탈퇴 처리
Cause

세션을 먼저 지우면 RLS에 막힌 UPDATE가 에러 없이 "0건 수정"으로 끝나 try/catch로도 잡히지 않습니다.

Fix

"소프트 삭제 → 세션 삭제" 순서로 고정했습니다.

V-04
오프라인 러닝 후 자동 동기화
Result

인터넷 없이 시작부터 종료까지 달린 기록이, Wi-Fi에 다시 연결되자 '동기화 대기' 표시 없이 자동으로 업로드됐습니다. local-first 설계가 실제 환경에서 의도대로 동작함을 확인했습니다.
